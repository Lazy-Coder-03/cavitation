# Changelog

Notable changes by release. Releases are git tags `vX.Y.Z`. New work goes under Unreleased.

## Unreleased

### Breaking changes

- `Init` has a new variant, `Normal { std }`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers later variants). Building a value, such as `Init::HeUniform`, works as before.
- `EpochReport` is `#[non_exhaustive]`, so a field added later is not a breaking change. Code outside `cavitation-nn` that builds one with a struct literal (to test a `StepControl`, say) uses `EpochReport::new(epoch, mean_loss, rows, seconds)`, which leaves `validation` as `None`. Reading the fields works as before; a struct pattern on it needs `..`.
- `LrSchedule::learning_rate` takes the step and the steps per epoch: `learning_rate(initial, step, steps_per_epoch, epochs)`. For the per-epoch schedules, epoch `e` is any step from `e · steps_per_epoch` to the end of that epoch, so the old `learning_rate(initial, e, epochs)` is `learning_rate(initial, e, 1, epochs)`. `LrSchedule` is `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm.
- `Health`, `HealthMonitor`, `Trainer`, `FitConfig`, `shrink::FromScratch` and `cavitation_ml::GradientConfig` take a lifetime parameter, and `Health::sink` and `FitConfig::on_epoch` are `Box<dyn FnMut(..) + Send + 's>`. The callbacks can borrow local state (a sink can push onto a `Vec` the caller reads after the run, without `Rc<RefCell<..>>`), and a `FitConfig` or a `Trainer` can be moved to another thread. A callback that captures something that is not `Send` (an `Rc`, a `Cell`) no longer compiles; borrow the value instead, or use `Arc` and an atomic or a `Mutex`. Code that names one of these types where a lifetime cannot be elided, such as a function with no reference arguments returning `FitConfig`, writes `FitConfig<'static>`; `TrainerHandle` and every `StepControl` are unchanged.

### Tensors and autograd (`cavitation-core`)

- SiLU and the tanh form of GELU run in f32 on the sigmoid and tanh SIMD kernels, on the tape (`Tape::silu`, `Tape::gelu` with `GeluApprox::Tanh`), in the `Silu` and `Gelu` layers' `Activation::f` and in `InferenceModel`, which agree bit for bit: `kernels::activation::silu_f32` (within 7 ulp of the correctly rounded value while the sigmoid is a normal number) and `gelu_tanh_f32` (within `|x| · 2⁻²¹` plus 2 ulp of the f64 value), with `_with` forms taking the level, and `Real::silu_in_place` and `Real::gelu_tanh_in_place`. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core of a machine with a load average of about 2.4: SiLU 14.04 ns per value with the scalar loop, 5.52 at `sse4.2` (2.5x); GELU's tanh form 34.24 ns, 7.42 at `sse4.2` (4.6x). f64 values are unchanged.
- The GLU's sigmoid, SiLU and tanh-GELU gates run on the same kernels, on the tape (`Tape::glu`) and in `InferenceModel`, which still agree bit for bit: each row's gate half goes through the kernel at once instead of one scalar value at a time. The gate values change in the last bits, within the kernels' bounds; the exact-GELU and ReLU gates are unchanged.
- `kernels::activation::softplus_f32` and `elu_f32(alpha, ..)`, with `_with` forms taking the level: softplus as `max(x, 0) + ln(1 + e^(−|x|))` and ELU's `e^x − 1` so that it keeps its relative accuracy near 0, on the exponential `tanh` and the sigmoid use and a new `log1p` on `(0, 1]`. Over every finite f32, softplus is within 2 ulp and `e^x − 1` within 1 ulp of the correctly rounded result. SSE4.2 runs them four lanes at a time with the reference loop's bits (softplus four vectors side by side, which on an Intel Celeron N5105 takes about half the time of one vector at a time), AVX2 eight lanes and NEON (and Accelerate) four lanes at a time with fused multiply-adds, within one ulp more (3 and 2 ulp, checked on a sweep of one f32 in 1,009 and the edge values). ELU keeps the sign of `−0` and is `alpha · x` for inputs under `2⁻²⁵` in size.
- Softplus, log-sigmoid, Mish, ELU, SELU and CELU run in f32 on those kernels, on the tape (`Tape::softplus`, `log_sigmoid`, `mish`, `elu`, `selu`, `celu`), in the layers' `Activation::f` and in `InferenceModel`, which agree bit for bit: `kernels::activation::softplus_beta_f32` (any `beta` and threshold), `log_sigmoid_f32`, `mish_f32` (softplus then tanh on blocks of 64 values), `selu_f32` and `celu_f32`, with `_with` forms taking the level, and the matching `Real` methods (`softplus_in_place`, `log_sigmoid_in_place`, `mish_in_place`, `elu_in_place`, `selu_in_place`, `celu_in_place`). Values change in the last bits, within the bounds each function's docs state; f64 values and every derivative are unchanged. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core of a machine with a load average of about 2.2, in ns per value, the scalar loop then `sse4.2`: softplus 25.68 → 9.09 (2.8x), log-sigmoid 24.12 → 7.95 (3.0x), Mish 72.61 → 16.28 (4.5x), ELU 11.62 → 5.26 (2.2x), SELU 12.73 → 5.36 (2.4x), CELU 12.67 → 6.30 (2.0x).
- The SSE4.2 `tanh`, sigmoid and ELU kernels also run four vectors side by side, with the same bits. Measured with `cavitation-bench activation` over 4,096 values on an Intel Celeron N5105, pinned to one core, in ns per value before and after: `tanh` 6.76 → 5.24, sigmoid 4.95 → 4.07, SiLU 5.51 → 4.73, GELU's tanh form 7.39 → 5.86, ELU 5.26 → 3.51, SELU 5.36 → 3.60, CELU 6.30 → 4.57, Mish 16.28 → 14.79.
- `Tensor::clone_from` and `ParamValues::clone_from` copy into the buffers the target already has when they are large enough, so copying the values of the same parameters again allocates nothing; before, they allocated a fresh copy as `clone` does.
- `Tensor::into_vec` gives up a tensor and returns its elements without copying them, so a tensor can grow in place through `from_vec`.
- When the thread pool cannot start a worker thread, it frees the memory it had set aside for that worker instead of keeping it for the rest of the process.
- `kernels::Level::ALL` lists every kernel level, in the order of their numbers, supported on this CPU or not (a slice, so a later level can be added without changing its type).
- `Tape::glu`, `softmax` and `log_softmax` on an input whose last axis has width 0, and `softmax_cross_entropy` and `nll` with no classes, now mark a parameter's gradient current in the backward pass, as every other operation does; it was left stale.

### Layers, training and inference (`cavitation-nn`)

- `Evaluator::refresh` on a model that runs on the tape (one with a layer of your own that has no inference form) copies the new parameter values into the evaluator's own in place when the model has the same layers as before, as on the compiled engine, so `fit`'s validation set allocates nothing from the second epoch on for such a model as well.
- Learning-rate schedules by step, with a linear warm-up: `LrSchedule::Warmup { steps }` climbs linearly to the optimiser's rate over the first `steps` steps (step `s` trains at `lr · (s + 1) / steps`) and then holds it, and `LrSchedule::WarmupCosine { warmup_steps, min_lr }` follows the warm-up with cosine annealing by step over the rest of the run (with `warmup_steps: 0`, PyTorch's `CosineAnnealingLR` stepped after every batch). `fit`, `fit_controlled` and `cavitation_ml`'s gradient path set their rate before every step; a run under one trains to the same parameters as a manual loop of `Trainer::step` calls at the same rates, bit for bit. `Constant` and `Cosine` still set the rate once per epoch.
- `Init::Normal { std }`: normal starting values with mean 0 and the given standard deviation, whatever the fans (PyTorch's `normal_(0, std)`, for recipes that say `std = 0.02`). A negative or non-finite deviation panics.
- `Dataset::extend` appends another data set's rows and targets after the existing ones without copying those, so collecting data in rounds costs time in proportion to the rows added. It panics, leaving the data unchanged, when the feature counts, the target kinds or the output counts differ.
- `save` records the model's layer kinds (`linear,relu,linear`) under `cavitation.layers` in the file's `__metadata__`, and `load` (and `load_with` with `strict` and no `rename`) returns `Error::Format` listing both when a file records other kinds: GELU-trained weights no longer load silently into a ReLU network (where the digits test set scored 339 of 360 instead of 345). Files without the record, PyTorch's among them, load as before; PyTorch ignores the metadata.
- `load`, `load_lenient` and `load_with` read `F16`, `BF16` and `F64` safetensors files as well as `F32` ones: half precision widens to `F32` exactly (subnormals, infinities and NaN payloads included), and `F64` rounds to the nearest `F32`, as PyTorch's `.float()` does, with a finite value beyond the `F32` range refused as `Error::Format` naming its key. Checked bit for bit against state dicts written by PyTorch in each type. `save` still writes `F32`.
- `StepLog`, a `StepControl` for `fit_controlled` that keeps one `StepRecord` per training step: its number, epoch, loss, rows and wall-clock seconds, and with `StepLog::with_update_times` the optimiser's update time from the step's profile (every step after the first recorded one is then profiled). `reserve` sizes its list once. A run without it is unchanged. Both are in the `cavitation` prelude.
- `shrink::ablate` (and `ablate_with`, `ablate_controlled`) runs the layers before each swept `Linear` once, keeping that `Linear`'s input for every row, and then only the layers from the `Linear` on for each of its neurons; the results are bit-identical. Sweeping the second hidden `Linear` of a 64 → 256 → 256 → 10 network over 1,000 rows: 2.67–2.78 s before, 2.22 s after (one thread pinned to one core, on an Intel Celeron N5105 at kernel level `sse4.2`). The gain grows with the share of the work before the swept layer; the first `Linear`'s input is the data, so its sweep is unchanged. The kept input takes `rows × width` values for the swept layer's input width.

### Data, examples, guide and benchmark

- The inspector's `epoch` event carries the run's validation (`EpochReport::validation`: loss, and accuracy or R²) as `validation`, `null` without a validation set, and the page shows it under the accuracy and loss beside the probe evaluation.
- `cavitation_datasets::mnist::load` reads each file's pixels and labels straight from the bytes read, instead of copying them into a second buffer first. The test that loads the real files is now ignored by default with its reason shown, rather than passing silently when the files are missing; run it with `cargo test --release -p cavitation-datasets -- --ignored mnist_real_files`, where missing files fail it with the download instructions.
- The inspector page labels the epoch-end accuracy and loss as from training rows when no `probe` set is given, instead of always calling them held out; the docs of `InspectorConfig::eval_rows`, the `epoch` event's `evaluation` and the inspector chapter say the evaluation is held out only with a probe set and point to the `model` event's `probe_is_training`.
- `cavitation_datasets::mnist::load` returns `Error::Format` naming the file for images that are not 28 by 28. Before, a header of 0 images with huge row and column counts passed the length check and gave a data set of shape `[0, rows · cols]`, where the product could overflow.
- `cavitation-bench` writes `results.json` under `CARGO_TARGET_DIR` (in its `bench` folder) when that is set, instead of always the workspace's `target/bench`; prints the usage text only for a command-line error, not after a failure while running (which now exits with status 1, not 2); and on aarch64 Linux, whose `/proc/cpuinfo` has no `model name`, names the CPU from its cores' `CPU implementer` and `CPU part` (`ARM Cortex-A76`, with the board's `Model` line when there is one) instead of `unknown`.
- The README lists all five guide chapters, in the guide's order, and "Coming from PyTorch" explains where a neuron mask goes in one paragraph instead of two that overlapped.

## v0.2.0 (2026-11-14)

### Breaking changes

- `EpochReport` has a new public field, `rows`, so code that builds an `EpochReport` with a struct literal must set it.
- `EpochReport` has a new public field, `validation: Option<Evaluation>`, so code that builds an `EpochReport` with a struct literal must set it (`validation: None`).
- `FitConfig` has a new public field, `validation: Option<Dataset>`. A struct literal that ends with `..FitConfig::default()` needs no change (the default is `None`); one that lists every field must add `validation: None`.
- `shrink::ShrinkConfig` has a new public field, `fold_means`, so code that builds a `ShrinkConfig` with a struct literal and no `..ShrinkConfig::default()` must set it.
- `OnNonFinite` has a new variant, `Skip`, and is now `#[non_exhaustive]`: a `match` on it outside `cavitation-nn` needs a wildcard arm (which also covers later variants). Building a value, such as `OnNonFinite::Stop`, works as before.
- `Linear::bias` returns `Option<ParamId>`, `None` for a layer without a bias. A layer from `Linear::new`, `with_init` or `from_values` always has one, so `layer.bias().unwrap()` is the old value.
- `InferenceLayer::Linear`'s `bias` field is `Option<Vec<f32>>`, `None` for a layer without a bias. A layer of your own that returns this form from `Layer::inference` builds it with `bias: Some(values)` (or `None` for no bias), and code that reads the field uses `bias.as_deref()`, which gives an `Option<&[f32]>`.

### Workspace

- The `cavitation` crate has two features: `ml` (on by default) re-exports `cavitation-ml` as `cavitation::cavitation_ml`, and `inspect` (off by default) re-exports `cavitation-inspect` as `cavitation::cavitation_inspect`. `default-features = false` leaves both out. `cavitation::prelude` adds `LinearRegression`, `LogisticRegression`, `LinearModel` and `LogisticModel` with `ml`, `Inspector` and `InspectorConfig` with `inspect`, and `Standardizer`, `Flow`, `fit_controlled`, `StepControl`, `StepInfo`, `StepProfile`, `ModelHandle` and `TrainerHandle` always.
- Doc comments are wrapped at 100 columns.

### Tensors and autograd (`cavitation-core`)

- New error variant, `Error::Net`, for an address the inspector cannot listen on. `Error` is `#[non_exhaustive]`, so this is not a breaking change.
- `Tape::backward_timed`: `backward` with bit-identical gradients that also adds the time between marks (each layer's output, say) to the caller's `times`, reading the clock only at the marks.
- `ParamGrads::like` makes a second gradient set for a store, allocated on first use, so a second backward pass leaves `ParamStore::grads` untouched; `ParamGrads::zero_grad` clears it.
- SIMD `tanh` and sigmoid for f32: `kernels::activation::tanh_f32` and `sigmoid_f32` (and `_with` variants that take a `Level`), with SSE4.2, AVX2 and NEON kernels and the scalar twins `kernels::reference::tanh_f32` and `sigmoid_f32`. Results are within 3 ulp of the correctly rounded value at every level (2 ulp at the reference and SSE4.2 levels, checked for every finite f32); the SSE4.2 kernel matches the reference bit for bit; a value's result does not depend on where it sits in the slice. `Tape::tanh` and `Tape::sigmoid` in f32 run them, as do the new `Real::tanh_in_place` and `Real::sigmoid_in_place` (`Real` is sealed, so adding methods breaks no code). f32 results change in the last bits; f64 is unchanged. On an Intel Celeron N5105 at SSE4.2, over 4,096 values, measured with `cavitation-bench activation` pinned to one core while the machine was busy (load average 5): tanh 7.3 ns per value against 29.7 ns for the scalar `f32::tanh` loop (4.1x), sigmoid 5.4 ns against 14.5 ns (2.7x).
- The backward pass of `Tape::binary_cross_entropy` with both inputs taking a gradient computes each element's logarithms once instead of twice, with the same gradients bit for bit: 3.29 ms before, 2.43 after for 65,536 values (forward and backward, one thread pinned to one core, on an Intel Celeron N5105 at kernel level `sse4.2`, load average about 2.5). The other two-input losses, `kl_div` included, are unchanged: their two gradients share no costly work, and the one-pass form measured no faster for `kl_div`.

### Classic machine learning (`cavitation-ml`)

- A new crate for classic models in `f64`, with no dependency outside the workspace.
- Least squares: `linalg::lstsq` and `linalg::Qr`, a Householder QR that scales columns by powers of two (so columns from about 1e-300 to 1e300 factor correctly) and names the first column that depends on the ones before it; `linalg::qr_reference` is its plain twin.
- `LinearRegression` (ordinary least squares, and ridge with `alpha > 0`): `fit` solves exactly by QR and matches scikit-learn's `LinearRegression` and `Ridge` within 1e-9; `fit_gradient` trains one `Linear` with a `GradientConfig` (by default 1,000 full-batch epochs of Adam with cosine decay). Both return a `LinearModel` with `predict`, `score` (R²), `to_sequential` (saves as a PyTorch `nn.Linear`) and `from_sequential`.
- `LogisticRegression` (scikit-learn's defaults: an intercept and `c = Some(1.0)`): `fit` solves two classes exactly by Newton's method, matching scikit-learn's `newton-cholesky` within 1e-8 and `lbfgs` within 1e-5; `fit_gradient` handles two or more classes. Separable classes without a penalty, a single class, and labels other than 0 and 1 are `Error::InvalidData`, each message suggesting what to change. Both return a `LogisticModel` with `predict_proba`, `predict`, `score` (accuracy), `objective` and `to_sequential`.
- `LinearModel::from_sequential` reads a `Linear` without a bias as a model whose intercept is 0 for every output.
- `fit_gradient` honours `OnNonFinite::Skip` in `GradientConfig::health`: a skipped step changes nothing and counts toward neither `mean_loss` nor `rows`, and an epoch in which every step was skipped ends the fit with `Error::NonFinite`.

### Inspector (`cavitation-inspect`)

- A new crate, built on `std::net` alone: `Inspector::start(InspectorConfig)` serves a live view of training to the browser on `127.0.0.1:7878` by default, and `Inspector::url` gives the address with a per-run 128-bit token. The server refuses requests without the token, with a `Host` other than its own address or with a foreign `Origin`; it never sends `Access-Control-Allow-Origin`, and GET changes nothing. Every connection has a read and a write timeout, and dropping the `Inspector` first gives clients up to 500 ms to read what is queued, then stops every thread within 1 s.
- `cavitation_inspect::fit` trains under the inspector. While a page is open it captures, at most `snapshot_hz` times a second (4 by default), the run's statistics, one probe row through every layer (a, z, f′(z), ∂L/∂a, ∂L/∂z), the chosen neuron and a per-layer step profile, and at epoch ends evaluates the model on the probe rows when the time since the last evaluation is at least `EVALUATION_FACTOR` (200) times its cost, at most about 0.5% of the run (always after the last epoch); when training ends with a page open, one last snapshot shows the final step and epoch. The page can switch neurons, override the learning rate, pause and resume, and pick the probe row and neuron; every command is checked. With no page open nothing is captured, and a run with no commands trains to the parameters of `fit`, bit for bit.
- The page: one self-contained HTML file built into the crate, with a strict Content Security Policy and no request outside its own server. It shows the run's figures, every layer as a heat map, the chosen neuron with the chain rule and its activation curve, the step profile, and the shrink lab. `Inspector::export_html` and `GET /export` save it with the run so far embedded, to open without a server.
- Explore mode: `Inspector::explore` serves a trained network to the page, which can switch neurons, rank a hidden layer's neurons by ablation, and shrink the network level by level, with `Cancel` ending a run after the step in progress.
- The neuron panel shows a neuron of a `Linear` without a bias with no bias and its sum as `Σ w·x`; the `neuron` event has a new field, `has_bias`, and `bias` is `null` for such a neuron.
- `sse::Hub`, `json::JsonWriter` (NaN and infinity as `null`, `<`, `>`, `&`, U+2028 and U+2029 escaped), `commands`, `probe::Probe` and `wire` (every event's fields) are public for programs that build their own view.
- A snapshot (`stats`, `probe`, `neuron`, `profile`) is no longer sent ahead of an event that is still waiting for the hub: while a `status`, `epoch` or `model` event that the hub's lock refused waits, no snapshot is taken, so a page sees a paused run's `paused` status before its paused `stats`. A `profile` the hub's lock refused is asked for again on the next step instead of being lost. In explore mode, commands sent before a ranking or a shrink run starts are read before its first neuron or level, so a cancel sent early always stops the run at its first stopping point.

### Layers, training and inference (`cavitation-nn`)

- A `Linear` without a bias, like PyTorch's `nn.Linear(inputs, outputs, bias=False)`: `Linear::without_bias` (the weight drawn as `with_init` draws it) and `Linear::from_weight` make one. It computes `x · Wᵀ`, its only parameter is `weight`, so `save` writes `{i}.weight` alone and a PyTorch `state_dict` of a bias-free layer loads with `load`; it matches PyTorch's forward pass and gradients (a new fixture, written with torch 2.15.0 by `make_fixtures.py --only no-bias`). Compiled inference skips its bias add, `compact` and `train_found_size` keep the layer without a bias, and `Standardizer::fold_into_input` and `fold_into_output`, which must write a bias, refuse it with `Error::InvalidData`, as does `shrink` with `fold_means` when the `Linear` after a listed layer has no bias.
- `fit_controlled` runs a `StepControl` after every step and epoch. The control gets a `StepInfo`, a `ModelHandle` that can change only the neuron masks, the parameters to read, and a `TrainerHandle` that can only ask for a `StepProfile`, override or read the learning rate and read the step count; `Flow::Stop` ends the run. `fit` and `fit_with_hooks` run the same loop with no control.
- `Trainer::override_learning_rate`, `Trainer::learning_rate`, `Trainer::profile_next_step` and `Trainer::last_profile` (each layer's forward and backward time, the loss, the optimiser and the whole step; steps not profiled read no clock and allocate nothing), and `Trace::set_timing` and `Trace::forward_time`.
- `Standardizer`: each column's mean and population standard deviation, `transform` and `inverse_transform`, and `fold_into_input` and `fold_into_output`, which write the scaling into the first or last `Linear` so a trained network takes raw inputs or answers in the targets' units.
- `shrink::ablate_controlled`: `ablate_with` whose callback returns a `Flow`, so a sweep can stop early.
- `ShrinkConfig::fold_means` (off by default): `shrink` folds each removed neuron's mean output on the training rows into the next `Linear`'s bias before retraining, measured on the network with the step's earlier layers already shrunk; for a neuron whose output is constant the network's outputs do not change, within rounding. `shrink::train_found_size` trains a network of the size a shrunk network has from new starting values (`shrink::FromScratch`: the weight and bias `Init`, a seed and the `FitConfig` recipe) and returns both networks' measures on the rows you give, with the fresh network, in a `shrink::FoundSize`; the `shrink_digits` example's `--lottery` uses it.
- `Loss::record` is public, so a tape of your own can record the training loss.
- `InferenceModel` runs `Tanh` and `Sigmoid` layers through the SIMD activation kernels, and `Activation::f` of the built-in `Tanh` and `Sigmoid` gives the same bits as the tape and compiled inference. On an Intel Celeron N5105 at SSE4.2, one input through a 4 → 32 → tanh → 32 → tanh → 1 network takes 841 ns against 353 ns for the same network with ReLU, measured with `cavitation-bench activation` pinned to one core while the machine was busy.
- `FitConfig::validation`: a held-out set that `fit`, `fit_with_hooks` and `fit_controlled` measure after every whole epoch with the run's loss, recorded in `EpochReport::validation` (the loss, and the accuracy or R²) before `on_epoch` runs. It is bit for bit what `evaluate` gives on the parameters and neuron masks as the epoch left them, follows the masks a `StepControl` changes, and after the first epoch allocates nothing for a model that compiles. An unsuitable validation set is `Error::InvalidData` before training, with a message that starts with `validation: `. A control that stops the run mid-epoch leaves that epoch without a validation.
- `Evaluator::refresh` copies new weights and mask values in place without allocating when the model has the same layers, the masks sit where they did and no clone shares its weights (it used to allocate on every call).
- `OnNonFinite::Skip`: a step whose loss or gradient is NaN or infinite sends the warning and is left out, leaving the parameters and the optimiser's state (momentum, moments, Adam's step counts) as they were, and training continues; with the other batches unchanged and in the same order (for example `shuffle_seed: None`), a run that skips a step ends with the parameters, bit for bit, of the run without that step's batch. Only `Skip` reads every gradient once more per step, before the update; `Stop` and `Warn` do not. A skipped step counts in `Trainer::steps` and in the new `Trainer::skipped_steps` and `TrainerHandle::skipped_steps`, but not in `EpochReport::rows`, `mean_loss` or the loss the vanishing-gradient check compares against; hooks still run on it, `StepControl::after_step` does not, and a profile asked for carries over to the next step that trains. An epoch in which every step was left out ends the run with `Error::NonFinite` naming the epoch. A hand-written loop asks the new `HealthMonitor::before_update` whether to apply each update.
- The docs of `OnNonFinite::Warn` say what it does: the update is applied, so a NaN loss or gradient reaches the parameters and from the next step every parameter.
- The docs of `OnNonFinite::Stop` say that a NaN or infinite gradient with a finite loss is found after the update has applied it, so the parameters already hold the NaN when the error comes back; `Skip` keeps the last good values.
- `Adam` and `AdamW` fold the bias corrections into two scalars per step (`lr / (1 − β₁ᵗ)` and `1 / √(1 − β₂ᵗ)`), as `torch.optim.Adam` does, so each element takes one square root and one division instead of three divisions; results can differ from before in the last bit, and still match `torch.optim` over the ten-step fixtures. Update of one 1,068,810-element parameter on one thread: 14.06 ns per element before, 11.62 after (1.21x; `CAVITATION_THREADS=1 taskset -c 2 cavitation-bench subnormal --steps 700`, the Adam blocks of steps 1 to 700, median of 42 blocks per build, builds alternated, on an Intel Celeron N5105 at kernel level `sse4.2` while the machine was busy, load average 2.6 to 4.5).
- `Sgd`, `Adam` and `AdamW` hand the chunks of every parameter of a step to the thread pool in one call, instead of one call per parameter, so a network of small parameters uses every thread for its update. The chunks and the order of the statistics' sums are unchanged, so results are bit-identical to before, for any thread count. Update of the digits network's 50,826 parameters at 4 threads: Adam 387–393 µs before, 218–280 after; SGD with momentum 176–182 before, 95–102 after (measured on an Intel Celeron N5105 at kernel level `sse4.2` while the machine was busy, load average about 3, three interleaved runs of 101 rounds; at 1 thread both versions take the same time).
- `InferenceModel::infer_batch` (and `infer_batch_observed`) run a batch of one row through `infer`'s matvec path on the calling thread, giving `infer`'s output bit for bit; it was the GEMM's, which can differ in the last bits on some kernel levels. ### Tensors and autograd (`cavitation-core`)

- `Real` (implemented for `f32` and `f64`, with `Real::erf` ported from FreeBSD msun and `Real::exp_m1` for `eˣ - 1` without cancellation), `Shape` (`Shape::new` panics if the element count overflows `usize`), `Tensor` with `TensorView` and `TensorViewMut`, and `Error` for the failures a caller can recover from (bad data, bad files, unsupported requests, non-finite values during training; `Error::NonFinite` carries an optional `detail` naming the cause). A weight file that does not fit a model is one `Error::Keys(KeyErrors)` listing every missing, unexpected, wrong-shape and wrong-type key (ten of each at most, with a count of the rest), the file's own first keys when none of the model's keys is there, and a hint when a weight looks transposed.
- `Rng` (xoshiro256++) seeded through `SplitMix64`; `Rng::range(lo, hi)` is below `hi` when `lo < hi`; equal bounds give `lo`.
- Reverse-mode automatic differentiation: `Graph`, `Tape` and `Var`, and the `ParamStore` that holds parameters and their gradients. `zero_grad` marks gradients stale without writing them; `ParamStore::iter_mut` gives `None` for a gradient nothing has contributed to since. A parameter whose value was reshaped through `value_mut` panics in `iter_mut` and in the backward pass, naming the two shapes.
- Tape operations, following PyTorch's definitions and boundary conventions:
  - arithmetic with NumPy-style broadcasting: `add`, `sub`, `mul`, `scale`;
  - `matmul` and `matmul_nt`, with gradients computed on strided views;
  - reductions: `sum`, `sum_axis`, `mean`, `mean_axis`;
  - activations: `relu`, `leaky_relu`, `tanh`, `sigmoid`, `gelu` (exact and tanh forms, `GeluApprox`), `elu`, `selu`, `celu`, `silu`, `mish`, `softplus`, `softsign`, `hardtanh`, `relu6`, `hardsigmoid`, `hardswish`, `log_sigmoid`, `prelu`, and `glu` with a `Gate` (GLU, GeGLU, ReGLU, SwiGLU); NaN passes through every one of them, in the gradient too; `elu`, `selu` and `celu` keep full precision for tiny negative inputs (and the sign of `-0.0`);
  - `softmax` and `log_softmax`, and `softmax_row` and `log_softmax_row` for one row;
  - losses, each taking a `Reduction` (`Mean`, `Sum`, `None`, `BatchMean`): fused `softmax_cross_entropy` in log-sum-exp form, `nll`, `mse`, `l1`, `huber`, `smooth_l1`, `binary_cross_entropy` (with `Tape::clamped_logs`, the count of logarithms clamped to -100), `binary_cross_entropy_with_logits` and `kl_div`; NaN input gives a NaN loss;
  - `keep_where`, the select behind neuron masks, matching `torch.where(keep != 0, x, 0)`: exactly 0 and no gradient where `keep` is 0, even for an infinite or NaN value or gradient there.
- User-defined operations: the `CustomOp` trait (forward, backward and output shape, generic over `Real`) and `Tape::custom`, with up to 4 inputs.
- `gradcheck` and `gradcheck_params`: a numerical gradient check in `f64` by central differences, with a report of every element outside the tolerance. Both take the inputs first and the closure last.
- Kernels, chosen at run time: `kernels::Level` (reference, SSE4.2, AVX2 with FMA, NEON, Accelerate), `set_level` and the `CAVITATION_KERNEL` override; `Level::Accelerate`, the default on Apple Silicon, runs matrix products through Apple's Accelerate framework (`cblas_sgemm`, one call per product on the calling thread, linked only on Apple Silicon targets) and everything else through the NEON kernels, falls back to the NEON matrix product for layouts BLAS cannot express (neither stride 1, overlapping or broadcast rows, sizes beyond `i32`) and for `alpha = 0`, and matches the reference within the GEMM tolerance like every other level (an Apple M4 trained MNIST at batch 128 in 0.35 s per epoch at this level, against 0.90 s at NEON and 0.38 s for numpy on Accelerate, measured with `cavitation-bench all`); the thread count (at the Accelerate level each matrix product is one Accelerate call, so `CAVITATION_THREADS` does not limit the threads Accelerate starts itself, which Apple's `VECLIB_MAXIMUM_THREADS` does; `threads`, `set_threads`, `CAVITATION_THREADS`; by default the number of performance cores on Apple Silicon, where an Apple M4 trained MNIST at batch 128 in 0.97 s per epoch on its 4 performance cores against 1.14 s on all 10 cores (NEON level, an earlier run than the Accelerate figures, which measured NEON at 0.90 s on the same setup; both with `cavitation-bench all`), and the number of logical cores elsewhere); a persistent thread pool (`kernels::pool::run` and `run_chunks`) that allocates nothing per call and runs a job of one task, or one given one thread, on the caller without waking a worker; the packed f32 GEMM `kernels::gemm::gemm_f32` (Goto-style blocking and packing, a microkernel per level, bit-identical results for any thread count; products under 2¹⁸ floating-point operations run on the calling thread, so a 4 → 32 → 32 → 1 network trains on 4 threads with the same CPU time as on one: 0.63 s instead of 2.56 s for 10 epochs at 4 threads, against 0.63 s on one thread, measured with `cavitation-bench small` on an Intel Celeron N5105); and `kernels::matvec::matvec_f32`, one input times a transposed weight matrix with an optional bias and fused ReLU. Every fast kernel has a reference twin and tests that they agree.

### Layers, training and inference (`cavitation-nn`)

- `Sequential` is `Clone`: a clone shares its layers (they never change after `push`, so a user layer with interior mutability, such as a `Mutex` field, is shared between the copies, and a layer need not be `Clone`) and copies its neuron masks. Clone the `ParamStore` too for an independent network: training the clone then leaves the original's values unchanged.
- `Init` (Xavier and He initialisers, zeros, constant), the object-safe `Layer` trait, `Linear` (weight `[outputs, inputs]` like PyTorch), a layer for every built-in activation plus `Softmax`, `LogSoftmax`, `Glu` and `Prelu`, `Activation` and `ActivationLayer` for activations of your own, and `Sequential` with `Trace` and PyTorch-style parameter names (`0.weight`, `2.bias`). `Sequential` checks the width between layers and names the layer that does not fit.
- Optimisers: `Sgd` (momentum, weight decay), `Adam` and `AdamW`, matching `torch.optim` over ten-step trajectories. Each updates its parameters in chunks of 16,384 elements over the thread pool, bit-identical to the plain loop that runs at the reference level, and collects each gradient's norm and finiteness (`GradStats`) in the same pass. A parameter that received no gradient since `zero_grad` is skipped, as PyTorch skips `grad is None`; Adam's bias correction counts each parameter's own updates. Momentum buffers and Adam's moments store any value below the type's smallest normal number (`Real::MIN_POSITIVE`) as 0, so they never pass through the subnormal range, where updates ran 13.7 (momentum) and 7.4 (Adam) times slower (Adam update on decayed state 28.6 ms before, 3.9 ms after; measured with `cavitation-bench subnormal` on an Intel Celeron N5105); a value PyTorch would keep as a subnormal is 0 here. `Sgd::momentum`, `Adam::moments` and `AdamW::moments` read the state, and `ParamId::position` gives a parameter's place in its store.
- Data: `Targets`, `Dataset`, `Batch`, `BatchView` and `Batcher` (shuffled batches whose smaller last batch reuses the full-size buffer).
- Training: `Trainer` (one step at a time; `step` returns the batch's loss or the health checks' error at the step that meets it), `Loss` (cross-entropy, NLL, MSE, L1, Huber, smooth L1, BCE, BCE with logits, KL divergence), `fit` and `fit_with_hooks` with `FitConfig`, `OptimizerConfig`, `LrSchedule` (constant, or cosine as PyTorch's `CosineAnnealingLR` stepped once per epoch), `History` and `EpochReport`, and `accuracy`. `fit` checks the data against the loss and the model before it trains and returns `Error::InvalidData` instead of panicking, naming the tensors and their shapes ("the inputs are [8, 5]", "the value targets are [1437, 1], but the model outputs [1437, 10]", "there are 100 rows but 99 labels"), including binary cross-entropy targets that are NaN or outside `[0, 1]`, and inputs of the wrong width (the message gives the width that reaches the layer when an activation or `Glu` comes before the first layer that names one); it also rejects any NaN or infinite input or value target, naming the row, the column and the value (two layers that disagree still panic in the forward pass, naming both); `accuracy` panics on a label not below the output width, as `fit` rejects it. The same seeds give bit-identical parameters for any thread count on the same machine and kernel level.
- Hooks: `Hooks` (with `HookId`) runs closures on chosen layers after each forward or backward pass; each sees a `LayerEvent` with the layer's input, output, local derivative and the gradients with respect to its output and input.
- Neuron masks: `NeuronMask` with `Sequential::set_mask`, `clear_mask` and `mask`; an off neuron outputs exactly 0 and passes no gradient.
- Health checks: `Health` (with `OnNonFinite`), `HealthMonitor` and `Warning`. Every step checks that the loss and each gradient are finite (by default training stops with `Error::NonFinite`, naming the step and `loss` or the parameter), warns when a gradient norm is above 1e3 or below 1e-7 (no vanishing warning once the loss has fallen 10,000-fold from its first value, which is convergence) and when binary cross-entropy clamps a logarithm, and each epoch reports ReLU and ReLU6 neurons that output 0 for every sample. When the loss is the non-finite value, the error and the warning name the cause: the first NaN or infinite input or target value (its batch position, its feature and, in a hand-written loop that passes `StepInputs::rows`, its dataset row; `BadInput`; `fit` rejects such data before training, with an error that names the row), or, when every input was finite, that the values overflowed and a lower learning rate is the thing to try; nothing is scanned on a healthy step. `Trainer` also warns, at most once per epoch (`Warning::NegativeLoss`), when a loss that cannot be negative on valid inputs (`Loss::non_negative`) comes out below 0, for example `Loss::Nll` on scores that are not log-probabilities. `HealthMonitor::after_backward` takes the step's `StepInputs`; `HealthMonitor::with_loss` turns the negative-loss check on for a hand-written loop. Every warning ends with a hint on what to try, and `Warning` has accessors (`kind`, `step`, `epoch`, `location`, `layer`) with `WarningKind`. Warnings go to a sink closure, which receives every one of every epoch, or to standard error, where printing is bounded: a layer's dead-neuron report (`247 of 256 (96%)`, the first 10 indices) is printed when its share first passes 25%, 50% or 90%, so a healthy run prints nothing, and an exploding or vanishing parameter is printed once and then summarised in one line per kind each epoch. `Health::quiet()` keeps every check and drops the warnings. A neuron masked on the `Linear` before a ReLU layer is not reported dead.
- Inference: `InferenceModel::compile` turns a `Sequential` and its parameters into a model that runs without the training graph; `infer` runs one input through the matvec kernels on the calling thread and `infer_batch` a batch through the GEMM. `InferenceLayer` and `Layer::inference` give every built-in layer an inference form.
- `save`, `load`, `load_lenient` and `load_with`: weights in the safetensors format, named as a PyTorch `state_dict`. Files written by `save` load in PyTorch with `safetensors.torch.load_file` (checked by `make_fixtures.py --check-rust-save` against a committed file that `save` must reproduce byte for byte), and files saved by PyTorch load here. `load_lenient` and `load_with` return the keys of the file they ignored (`load_with`: none when `strict`). `load_with` takes `LoadOptions` (`strip_prefix("module.")`, or a `rename` closure for shifted indices; `strict` applies to the renamed keys; two keys renamed to one are an error naming both). Loading checks every key, shape and the F32 type before it writes anything, and a `torch.save` file (a zip archive or a pickle) gets an error that says to save with `safetensors.torch.save_file`.
- After a warm-up, a training step, a hooked or masked step, the health checks and both inference paths allocate nothing.
- `Level` and `Warning` are `#[non_exhaustive]`, so a later kernel level or warning is not a breaking change; a `match` on either needs a wildcard arm.
- `Default` for the parameterised activations with PyTorch's defaults (`Gelu` exact, `LeakyRelu` slope 0.01, `Elu` and `Celu` alpha 1, `Softplus` beta 1 and threshold 20, `Hardtanh` -1 to 1), and `Trace::with_capacity` is public so a manual loop can size its trace once (it saves the first pass's allocation). The docs now say that `AdamW`'s default decay can keep a run from settling on a minimum away from 0, that "dead" neurons are measured per epoch and per data, why a PyTorch loop's mean loss differs from `EpochReport::mean_loss` when the last batch is short (with the loop that matches), and how to rebuild the digits split outside the repository.
- Layers and masks by `Linear`: `Sequential::linear`, `linears` and `param` (`"2.bias"`, no allocation), `as_linear` on `dyn Layer` (sealed: only `Linear` answers it), `Layer::parameter` and `Layer::is_elementwise` (which says where a neuron mask lands), `Linear::from_values` for weights trained elsewhere, `NeuronMask::from_off`, `from_on`, `all_off`, `on`, `off` and collecting from bools, and `Sequential::neuron_layer`, `set_neuron_mask`, `neuron_mask`, `clear_neuron_mask` and `set_neuron`, which address a hidden neuron by its `Linear` and put the mask on the last layer of the run of element-wise layers after it (on `Linear → Tanh → Sigmoid` the `Sigmoid`, so an off neuron sends exactly 0), or on the `Linear` itself when no element-wise layer follows (`set_neuron` on an existing mask allocates nothing). `set_neuron_mask` and `set_neuron` check the mask's width against the `Linear`'s output width at once and panic naming the `Linear` and both widths, and refuse to add a neuron mask while the `Linear` itself carries a mask set with `set_mask` (which `neuron_mask` and `clear_neuron_mask` do not see), so one set of neurons never carries two masks. The health check's dead-neuron report treats a mask anywhere in that run as deliberate.
- Held-out measurement: `Evaluator` (`new`, `refresh`, `evaluate`, `misclassified`) and the one-shot `evaluate` return an `Evaluation` with the loss (each batch's training loss weighted by its row count, as `EpochReport::mean_loss` is), the accuracy for class targets and R² for value targets (scikit-learn's `r2_score`, averaged over the outputs); they run the compiled inference model, or the tape for a model with a layer that has no inference form, return `Error::InvalidData` for data that does not suit the model or the loss (a label not below the output width names the row, the label and the width), and allocate nothing once they have seen data of that shape (`refresh` aside), on either path. `refresh` copies new weights into the compiled model in place unless a clone shares them or the layout changed, when it compiles afresh; the mask values are each evaluator's own, never a clone's, and are copied in place whenever the masks sit on the same layers. `Evaluator::with_neuron_masks` gives chosen `Linear`s' neurons a mask, and `Evaluator::set_neuron_mask` switches them per evaluator without allocating, compiled or on the tape (where it changes the evaluator's own copy of the model), for an ablation sweep; `refresh` keeps those masks. `Evaluation` is `#[non_exhaustive]`, so a later measure is not a breaking change. `accuracy`'s docs point to `evaluate`, which returns an error where `accuracy` panics. `Dataset::split_at` and `Dataset::subset` copy rows out of a data set.
- Reading a network outside training: `InferenceModel::infer_batch_observed` calls a closure with each layer's output (masked, as the next layer receives it) as the batch runs, in layer order; a `Linear` fused with the ReLU after it reports the ReLU's layer only. The keep values of a compiled model's masks now belong to each instance, so clones share the weights but not the masks: `InferenceModel::compile_with_neuron_masks` adds an all-on mask step for chosen `Linear`s' neurons (at `Sequential::neuron_layer`), and `InferenceModel::set_neuron_mask` changes one in place without allocating; `compile_with_masks` and `set_mask` do the same by layer index (`Error::Unsupported` for neurons or a layer with no mask step, `Error::InvalidData` for a mask of the wrong width or an index that is not a `Linear`). A new public module, `cavitation_nn::shrink`, holds the tools for shrinking a trained network, outside the crate root and the prelude: `shrink::activity` measures each neuron of chosen `Linear` layers over a data set on the batched inference path (or on the tape, for a model with a layer that has no inference form), read where its output is final (after the activations, at `Sequential::neuron_layer`), and returns a `shrink::LayerActivity` per layer (`#[non_exhaustive]`) with the mean, mean absolute value, firing share (rows above 0) and maximum; with no `Linear` listed it returns an empty list without running the data.
- `shrink::compact` removes switched-off neurons for good: it rebuilds a masked network as a smaller dense one in a new parameter store (each masked hidden `Linear` keeps the rows of its on neurons, the next `Linear` the matching columns, a per-channel `Prelu` between them the matching slopes; layer indices stay, so the result saves and loads like any network). For finite weights its outputs equal the masked network's bit for bit on the `reference` and `sse4.2` kernel levels, through `InferenceModel::infer` and, while every summed length is at most 256, through the batched paths; on `avx2`, `neon` and `accelerate`, where an output's rounding depends on its position, each network is within the documented matvec and GEMM rounding bound of the exact result. It returns `Error::Unsupported`, naming the layer and what to do, for a mask on the output layer, a removed neuron that passes an element-wise layer with f(0) ≠ 0 after the last mask that switches it off (mask by `Linear` with `set_neuron_mask` instead), a mask that does not reach the next `Linear` through element-wise layers, a layer of your own with parameters, a layer other than an activation or a `Prelu` after a `Linear` that loses neurons, and a `Linear` left with no neuron; masks with every neuron on are dropped. `as_prelu` on `dyn Layer` finds a `Prelu`, sealed the same way: only the crate's own `Prelu` answers it.
- `shrink::ablate` and `shrink::ablate_with` switch each neuron of chosen hidden `Linear`s off in turn and rank them by what its absence costs (accuracy points lost for class targets, relative loss increase for value targets), on one `Evaluator` with no recompiling per neuron; neurons already off are skipped and stay off, and the model is not changed.
- `shrink::shrink` finds the smallest network that is still as good: it removes neurons of the hidden `Linear`s a step at a time with neuron masks (levels in basis points: 10% steps to 70%, then 5% steps to 95%, each layer keeping at least one neuron), neurons whose output is 0 on every training row first and then the lowest-ranked (`shrink::Ranking`: outgoing-weight norm by default, mean activity, seeded random, or your own function given a `shrink::RankContext`), retrains after each step with a fresh optimiser (`shrink::RetrainConfig`: 3 epochs of Adam at 1e-3 by default; a NaN or infinite loss or gradient returns `Error::NonFinite`), and measures each step on a validation set (`shrink::Validation`, given or carved from the end of the training rows; there is no default). It keeps the latest step that meets `shrink::Criterion` (at most 1 accuracy point lost by default for class targets, counted in whole rows; value targets must name a loss criterion), stops after 2 misses in a row or when `on_step` returns the new `Flow::Stop`, leaves the model and parameters at the kept step (or as given if none met it), and returns a `shrink::ShrinkReport` with the baseline, every `shrink::ShrinkStep` (kept neurons, the parameter count once compacted, the validation measures, and optionally a checkpoint) and a `shrink::ShrinkWarning` when one validation row is worth more than half the allowed drop, or when `compact` will not be able to rebuild the result (`NotCompactable`, naming the layer: a layer of your own with parameters, or an element-wise layer of your own after a shrunk `Linear`; the result then runs masked). Networks whose masked neurons would still reach the next `Linear` (through a `Softmax` or a `Glu`, say) are refused with `Error::Unsupported` before any training. `Ranking`, `Criterion`, `Validation` and `ShrinkWarning` are `#[non_exhaustive]`.

- Shrinking, end to end: the `shrink_digits` example (train on 1,149 of the training digits, `shrink` on the other 288, `compact`, save; `--ablate` switches neurons off one at a time and sweeps them with `ablate`, `--lottery` trains the found size from the kept neurons' initial weights and from new random weights, for as many epochs as the pruned network had), the ignored known-result test `shrink_known_result` (ranking by outgoing-weight norm without dead neurons first removes 75% of the 384 hidden neurons, the defaults 75% too, each within 1 test point of the unpruned network), `cavitation-bench shrink` (both runs' curves, a bit-for-bit check of the compacted networks on the 360 test digits, and `infer` timed for the full and the compacted network: 6.81 µs against 1.01 µs, 6.77× faster, measured with `cavitation-bench shrink` pinned to one core on an Intel Celeron N5105, kernel level `sse4.2`), and the guide's chapter "Shrinking a network".
- `cavitation-bench` (`all`, `mnist`, `cifar`, `digits`, `latency`, `gemm`, `subnormal`, `small`, `info`) times training and inference against a numpy baseline measured in the same run on the same network, batch, data and step count. Measured with `cargo run --release -p cavitation-bench -- all` on an Intel Celeron N5105 (4 cores, SSE4.2, no AVX), release build, kernel level `sse4.2`, 4 threads, plain SGD, numpy 2.4.4, rustc 1.99.1 (the figures of this run): an MNIST epoch of the 784 → 1024 → 256 → 10 network takes 6.17 s at batch 128 (numpy 9.35 s) and 10.19 s at batch 32 (numpy 14.61 s); the digits network trains at 116,904 samples/s (numpy 86,787); one input through the digits network in inference mode takes 6.77 µs (numpy 32.35 µs). `small` trains a small network at 1 and at 4 threads, each in its own process, and prints the wall-clock and CPU time of each (CPU time on Linux only). `cifar` trains the 3072 → 1024 → 512 → 10 network with Adam (lr 1e-3) on CIFAR-10's 50,000 training images at batch 128 and 32, in seconds per epoch, or with `--steps N` in steps per second over timed runs of N steps (cavitation's timed runs include the health scan at the end of each, which numpy's do not, so at small N the steps-per-second figure slightly understates cavitation); `all` leaves it out because its epochs take minutes on a small machine. Measured in a separate run, with `cavitation-bench cifar --steps 200`, on an Intel Celeron N5105 (4 cores, kernel level `sse4.2`, 4 threads, numpy 2.5.4, rustc 1.99.1, other processes using 70% of one core during the run): 12.78 steps/s at batch 128 (numpy 6.09) and 24.32 steps/s at batch 32 (numpy 12.19).
- `cavitation-bench` reads the load average on macOS too (from `sysctl -n vm.loadavg`), so its report no longer says "load average at the end unknown" there.
- Each training benchmark of `cavitation-bench` prints a summary of the health warnings it raised after its timing lines, grouped by kind and layer, with the first epoch of each group (for example `health: 4 warnings: DeadNeurons (layer 3, from epoch 1) x3; DeadNeurons (layer 5, from epoch 1) x1`), and `results.json` carries it as `health`. The summary is formatted after the timed region.
